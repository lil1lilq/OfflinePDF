# 오프라인 PDF 업무도구

Windows x64에서 문서를 외부로 보내지 않고 처리하는 한글 데스크톱 프로그램입니다.
**현재 버전은 0.1.0 시범 배포용입니다.** 실제 기관 PC의 Windows·백신 환경에서 검수한 후 전국 배포하세요.
PyMuPDF의 **오픈소스 버전만** 사용하며 Pro·상용 키·외부 API·클라우드 서비스를 사용하지 않습니다.
프로그램 소스는 **AGPL-3.0-or-later**로 제공합니다.

## 직원이 사용하는 방법

배포 담당자가 만든 `OfflinePDF-Setup-Windows-x64.exe`를 실행해 설치하고
바탕화면의 **오프라인 PDF 업무도구** 아이콘을 두 번 클릭합니다.
직원 PC에는 Python·인터넷·계정이 필요하지 않습니다.

설치가 제한되면 `OfflinePDF-Windows-x64-portable.zip`을 압축 해제하고
`OfflinePDF/OfflinePDF.exe`를 실행합니다. 폴더 안의 다른 파일을 삭제하거나 이동하지 마세요.

1. 왼쪽에서 작업을 선택합니다.
2. **파일 추가**에서 파일 여러 개를 선택합니다.
3. 페이지·회전 각도 등 필요한 설정을 입력합니다.
4. 승인된 **로컬 저장 폴더**를 선택하고 **실행**을 누릅니다.
5. **결과 폴더 열기**에서 새 파일을 확인합니다.

기존 원본은 덮어쓰지 않습니다. 결과는 `PDF결과_날짜시간_식별자`라는 새 폴더에 저장됩니다.
한 작업에 여러 파일을 넣었을 때 일부 파일에서 오류가 나면 **해당 작업 전체 결과를 취소**합니다.
오류가 있는 파일을 목록에서 제외한 뒤 다시 실행하세요.

## 구현된 기능

| 기능 | 범위 |
| --- | --- |
| 병합 | 목록 위에서 아래 순서로 모든 페이지 병합 |
| 분할 | 지정 페이지마다 별도 PDF |
| 추출·재배열·복제 | `3,1,1,2`, `5-1`처럼 원하는 순서 입력 |
| 삭제·회전 | 지정 페이지 삭제, 시계 방향 90·180·270도 |
| 압축 | 미사용 객체 정리와 무손실 압축. 압축률을 보장하지 않음 |
| PDF → PNG·JPG | 페이지 지정, 72~300 DPI |
| PNG·JPG → PDF | A4 세로·가로, 20pt 여백 |
| 암호 설정 | AES-256, 입력은 최대 40자 |
| 암호 해제 | 소유자 암호로 인증한 문서 |
| 워터마크·쪽 번호 | 한글 문구, 크기·불투명도, 시작 번호 |
| 서명·직인 | 오른쪽 아래 이미지 삽입. 인증서 전자서명은 아님 |
| 여백 자르기 | 네 방향 동일 여백. 가려진 데이터는 남음 |
| 문자 추출 | UTF-8 TXT. 스캔 이미지의 문자는 OCR 필요 |
| 영역 영구 삭제 | 한 PDF씩, 미리보기 드래그로 지정. 첨부·양식·주석·링크·메타데이터 함께 정리 |
| 부가정보 정리 | 속성·첨부파일·JavaScript 등 정리. 본문 비식별화는 아님 |
| 검색 가능한 PDF | 동봉된 한국어·영어 `traineddata`를 사용한 오프라인 OCR |

파일을 운영체제에서 끌어놓는 기능은 이번 버전에 포함하지 않습니다. **파일 추가**에서 Ctrl·Shift로 여러 파일을 선택합니다.
GUI의 파일 순서 변경은 **위로·아래로** 버튼으로 합니다. 페이지 순서는 입력 칸으로 지정합니다.
Office·HWP 변환, PDF/A, PDF 비교, 스캐너 직접 제어, 인증서 전자서명은 포함하지 않습니다.

## 암호와 영구 삭제

- 암호화 파일을 수정하면 입력 암호 또는 별도로 지정한 새 암호로 결과 PDF도 암호화합니다.
- TXT·이미지 출력과 **암호 해제** 결과에는 암호가 적용되지 않으므로 실행 전 확인창을 표시합니다.
- 병합하는 암호화 문서들의 입력 암호가 다르면 같은 작업에서 처리할 수 없습니다. 개별 처리하세요.
- 서명된 문서는 변경으로 서명 검증에 영향을 줄 수 있어 작업 전에 안내합니다.
- 영구 삭제는 지정한 영역만 처리합니다. 같은 정보가 다른 페이지·영역에 있으면 추가 지정해야 합니다.
- 잘린 PDF는 숨겨진 영역에 정보가 남을 수 있어 영구 삭제를 거부합니다. 자르기 전 원본을 사용하세요.
- 영역 삭제 결과는 텍스트 검색·복사·추출과 이미지 확인으로 검수하세요. 자동 개인정보 탐지 기능은 없습니다.
- 병합·재배열은 모든 책갈피·양식 구조·전자서명을 보존한다고 보장하지 않습니다. 결과를 검수하세요.

## 오프라인·개인정보 처리

실행 코드에는 HTTP 요청·원격 분석·자동 업데이트가 없습니다. 앱과 작업 프로세스는 Python socket 연결도 차단합니다.
이 가드는 운영체제 방화벽·악성코드 방어를 대체하지 않습니다. 배포 검수 시 방화벽으로 외부 통신을 차단하고 시험하세요.

문서·비밀번호·경로·미리보기를 디스크 로그로 수집하지 않습니다. PDF 처리 중 문서와 암호는 메모리에 존재합니다.
작업 중간 출력은 선택한 결과 폴더 안의 `.offline-pdf-` 임시폴더에서 작성하며 정상 실패·취소 시 정리합니다.
전원 차단·프로세스 강제 종료 시 남은 임시폴더는 파일 탐색기에서 삭제하세요. 파일 삭제는 저장장치 완전 소거를 의미하지 않습니다.

UNC 경로는 거부하며, 알려진 OneDrive 경로와 Windows 네트워크 드라이브도 차단합니다.
모든 동기화 도구·정션·백업 경로를 자동 판별할 수는 없습니다. OneDrive·Dropbox·Google Drive와 동기화되지 않는
승인된 로컬 폴더만 사용하세요. 프로그램은 기존 문서에 붙어 있는 외부 동기화 정책을 바꾸지 않습니다.

## GitHub에서 Windows 실행파일 만들기

이 소스 ZIP에는 **미리 빌드한 Windows EXE가 들어 있지 않습니다.** Windows 실행파일은 Windows 환경에서 빌드합니다.

1. GitHub에 새 저장소를 만들고 **압축을 해제한 내용 전체**를 저장소 루트에 올립니다. `.github` 폴더도 포함해야 합니다.
2. 저장소의 **Actions → Build Windows x64 → Run workflow**를 선택합니다.
3. 완료된 실행의 **Artifacts → OfflinePDF-Windows-x64**를 내려받아 압축을 풉니다.
4. `OfflinePDF-Setup-Windows-x64.exe`는 설치용, `OfflinePDF-Windows-x64-portable.zip`은 압축 실행용입니다.
5. Windows 시범 PC에서 실행·보안 검수 후 직원에게 배포합니다.

워크플로는 GitHub Actions 사용이 허용된 저장소와 패키지 다운로드가 가능한 **빌드 환경**에서 동작합니다.
최종 직원용 프로그램은 인터넷을 사용하지 않습니다. 워크플로는 공개 릴리스 게시를 자동 수행하지 않습니다.
제공된 빌드 설정은 이 작성 환경에서 GitHub Actions로 실행하지 않았으므로 첫 실행 결과를 확인해야 합니다.

## Windows에서 직접 빌드

빌드 담당자만 Python **3.12 x64**와 Inno Setup **6.x**를 설치합니다. 빌드 도구도 오픈소스입니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
powershell -NoProfile -ExecutionPolicy Bypass -File packaging\build_windows.ps1 -Python .\.venv\Scripts\python.exe
```

스크립트는 자동 시험을 통과하면 `release` 폴더에 배포 파일을 만듭니다.
기관 정책이 스크립트 실행을 제한하면 전산부서의 허용된 빌드 절차를 사용하세요.
코드서명 인증서는 포함하지 않습니다. 전국 배포 시 기관 인증서로 실행파일·설치파일을 서명하고 실제 백신 환경에서 확인하세요.

### 인터넷 없는 빌드 환경

동일한 Windows x64·Python 3.12 온라인 준비 PC에서 휠을 먼저 확보합니다.

```powershell
python -m pip download -r requirements-build.txt --only-binary=:all: -d wheelhouse
```

전체 프로젝트, `wheelhouse`, 해당 Python·Inno Setup 오프라인 설치본을 내부망으로 전달한 뒤
`build_windows.ps1 -Offline`을 실행합니다. 대응 소스 자료도 아래 안내대로 미리 준비해야 합니다.

온라인 준비 PC에서 `python packaging/prepare_dependency_sources.py`를 실행하고 생성된
`dependency-sources` 폴더도 전달합니다. PyMuPDF 1.26.6과 포함 MuPDF 1.26.11의 원본 소스 자료를
배포본에 함께 넣기 위한 빌드 전용 단계입니다. 용량이 커서 다운로드 시간이 추가됩니다.
오프라인 빌드는 `sources.json`의 SHA256과 파일이 일치하는지 확인합니다.

## OCR 언어자료

`tessdata` 폴더에 Tesseract 공식 `tessdata_fast`의 한국어·영어 모델을 포함했습니다.
원본 커밋과 SHA256은 `tessdata/models.json`, Apache-2.0 고지는 `tessdata/LICENSE`에 있습니다.
빌드 시 함께 포함되며 실행 중 다운로드하지 않습니다. 소스 실행 시에도 포함된 폴더가 기본값입니다.

스캔을 페이지별로 렌더링해 검색 가능한 PDF로 만듭니다. 기존 링크·양식·책갈피 구조를 유지하는 OCR이 아닙니다.
영문과 한글 OCR을 시험했으며 한글에는 오인식이 있었습니다. 원본 품질에 따라 정확도가 달라집니다.
실제 Windows 배포본에서 업무 표본으로 인식 품질과 엔진 지원 여부를 최종 검수하세요.

## 개발과 검증

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python main.py
```

Python 3.12와 PyMuPDF 1.26.6 기준으로 처리 엔진을 시험했습니다.
버전은 재현성을 위해 고정했으며 최신 버전을 뜻하지 않습니다. 의존성 변경 시 같은 시험과 보안 검토를 다시 수행하세요.
자세한 검증 범위·미검증 항목은 `TEST_REPORT.md`를 참고하세요.

## 소스 공개와 배포

프로그램의 대응 소스는 `CorrespondingSource.zip`으로 실행파일과 함께 배포합니다.
이는 이 프로젝트의 소스·빌드 스크립트입니다. 제3자 라이브러리의 대응 소스 자료도 함께 제공해야 합니다.
빌드 스크립트는 PyMuPDF·MuPDF의 대응 소스를 `dependency-sources`에 수집해 실행파일과 함께 넣습니다.
GitHub 저장소에는 문서나 실제 개인정보 대신 소스와 가명 테스트 자료만 올리세요.
`LICENSE`, `THIRD_PARTY_NOTICES.md`, `licenses`의 고지 및 최종 배포 구성요소의 라이선스 의무를 유지하세요.
